## 1. What this project is (simple version)

  repo root (`index.html`, `shop.html`, `product.html`, `cart.html`,
  `checkout.html`, `login.html`, `signup.html`, `account.html`,

  `orders.html`, `customers.html`, `settings.html`, plus

  `functions/api/products.js`, re-exported by

  Schema lives in `migrations/0001_initial.sql`.

  NEVER used in code yet.
- Live site runs on the free startup stack idea: Cloudflare for
  hosting + own database for data + own login system + no big bills.

## 2. What is broken today (must fix)

1. **Customer login is fake.** `login.js` / `signup.js` / `account.js`
   store `{firstName,lastName,email,password}` in `localStorage`
   key `xUser` with the password in PLAIN TEXT, plus flag
   `xLoggedIn=true`. Changing browser = account lost.
2. **Checkout is fake.** `checkout.js` builds an order object and saves
   to `localStorage` (`xLastOrder`, `xOrders`), clears `xCart`, goes to
   `order-confirmation.html`. It never calls the API. Owner sees nothing.
3. **Admin login is fake.** `admin/login.html` hardcodes
   `admin@elle.com / admin123` and just sets
   `localStorage xAdminAuth={u:'admin'}`. `admin/js/admin.js`
   `requireAuth()` only checks that key. Anyone can bypass.
4. **API has NO login check.** `functions/api/products.js` lets anyone
   `POST/PUT/DELETE /api/products`, `GET /api/orders`,
   `GET /api/customers`, `PUT /api/settings`. No middleware.
5. **Missing write routes.** There is NO `POST /api/orders` and NO
   `POST /api/customers`. Even a fixed checkout has nowhere to send.
6. **Filter bug.** `handleGetProducts` does `if (active !== null)` —
   but `URLSearchParams.get()` returns `null` when missing, so the
   check is ALWAYS true and appends `AND active = ?` with `0` even
   when no filter was asked. Same for `featured`. Fix: check
   `if (active !== null && active !== "")`.
7. **Admin dashboard is hardcoded.** `admin/index.html` shows
   `15 / 14 / 24 / 8` and 3 fake orders. `admin/js/admin.js` has
   `MOCK_PRODUCTS` (3 items). Nothing fetches the API.
8. **Secrets in plain vars.** `wrangler.toml [vars] ADMIN_EMAIL`
   is fine, but there must NEVER be a password in `[vars]`.
   Use `wrangler secret put ADMIN_PASSWORD_HASH`.

### Phase 1 — Admin lock (highest priority)

**1a. New migration `migrations/0002_auth.sql`:**

```sql
ALTER TABLE customers ADD COLUMN password_hash TEXT;
ALTER TABLE customers ADD COLUMN phone TEXT;
ALTER TABLE customers ADD COLUMN address TEXT;
ALTER TABLE customers ADD COLUMN city TEXT;
ALTER TABLE customers ADD COLUMN country TEXT;
ALTER TABLE orders ADD COLUMN customer_email TEXT;
ALTER TABLE orders ADD COLUMN number TEXT;
CREATE UNIQUE INDEX IF NOT EXISTS idx_orders_number ON orders(number);
CREATE INDEX IF NOT EXISTS idx_orders_email ON orders(customer_email);
```

Do NOT seed passwords. Admin seed happens via secret script below.

**1b. Password hashing (Workers-safe, no bcrypt):**

- Use WebCrypto PBKDF2-SHA256, 100k iterations, 16-byte random salt:
  store as `pbkdf2$100000$saltB64$hashB64`.
- One-off seed script (run locally, NOT committed):
  generate the hash with node, then
  `wrangler secret put ADMIN_PASSWORD_HASH` + insert admin row via
  `wrangler d1 execute` with email from `ADMIN_EMAIL`.
- Login verifies with a timing-safe compare.

**1c. New routes in `functions/api/products.js`:**

- `POST /api/admin/login` with `{email,password}` -> verify against
  `admin_users`, create session `sid = crypto.randomUUID()`,
  KV SESSIONS put `admin:<sid>` with 12h TTL, set cookie
  `x_admin_session=sid; HttpOnly; Secure; SameSite=Lax; Path=/`,
  return `{ok:true, admin:{email,name}}`. Update `last_login_at`.
  Rate-limit: max 10 fails per 10 min per IP (counter in KV).
- `POST /api/admin/logout` -> delete KV key, clear cookie.
- `GET /api/admin/me` -> read cookie OR `Authorization: Bearer`,
  validate KV, return admin or 401.
- `GET /api/admin/stats` (protected) -> real counts from D1:
  `{totalProducts, activeProducts, orders, customers, revenue}`.

**1d. Auth middleware in the router:**

- Public (no session): `GET /api/products*`, `GET /api/health`,
  `POST /api/orders`, `POST /api/admin/login`.
- Protected (require admin session, else 401 JSON):
  `POST/PUT/DELETE /api/products*`, `GET/PUT /api/orders*`,
  `GET /api/customers*`, `GET/PUT /api/settings`,
  `GET /api/admin/me`, `GET /api/admin/stats`.
- Helper `requireAdmin(request, env)` returns admin or null.
  Parse cookies manually from the Cookie header.
- Keep CORS + OPTIONS handling exactly as today.

**1e. Fix `handleGetProducts` filters:**

```js
if (active !== null && active !== "") { ... active === "true" ? 1 : 0 }
if (featured !== null && featured !== "") { ... }
```

Add `search` param (name/description LIKE), cap limit at 100.

**1f. Wire admin frontend (keep same look):**

- `admin/login.html`: replace inline script with fetch to
  POST /api/admin/login. On ok go to index.html. On fail show error.
  REMOVE hardcoded admin email/password values and REMOVE
  localStorage xAdminAuth.
- `admin/js/admin.js`: replace requireAuth with async fetch to
  GET /api/admin/me + redirect on 401. Logout calls
  POST /api/admin/logout. Replace MOCK_PRODUCTS with
  fetch GET /api/products and GET /api/admin/stats.
  Keep TAXONOMY enforcement as-is.
- `admin/index.html`: replace hardcoded stats + fake order rows with
  data from GET /api/admin/stats + GET /api/orders?limit=5.

### Phase 2 — Real orders + customers

**2a. POST /api/orders (PUBLIC, guest checkout allowed):**

Request: `{email, firstName, lastName, phone, address, city, postal,
country, items:[{id, quantity}], delivery:{method}}`.

Server MUST:
- Look up each id in D1 products (must be active=1).
  Reject unknown/inactive with 400.
- Compute subtotal from D1 prices, NOT client total.
  shipping = 12 if method is express else 5.
  total = subtotal + shipping.
- Generate number like X1001+, id = crypto.randomUUID().
- Upsert customer by email into customers table.
- D1.batch insert into orders + order_items in one go.
- Return `{order:{id, number, subtotal, shipping, total, items}}`.

**2b. POST /api/customers + PUT /api/customers/:id (protected):**
Upsert by email for admin-created customers.

**2c. Wire checkout.js:**

- Keep validation + delivery/price UI exactly as-is.
- After buildOrder(), POST to /api/orders with cart + contact fields.
- On success: keep existing localStorage saveOrder (for
  order-confirmation page), clear cart, go to confirmation.
- On API fail (offline/dev): still complete locally so demo never
  breaks, but log the error. Do NOT block checkout when API is down.

**2d. Products read from API with fallback:**

- products.js static PRODUCTS stays as fallback.
- shop.js / product.js: try GET /api/products first, fall back to
  window.PRODUCTS on fail. No UI change.

### Phase 3 — Real customer accounts

- POST /api/auth/signup {firstName,lastName,email,password}:
  validate email + password >= 8, reject duplicate 409,

  Fall back to localStorage xOrders if API down.
- checkout.js gate: keep login-required behavior, but check
